### What "0 mismatches" covers

The vectors hold the inputs constant for each of 1,526 segments, which together span 13,239,637
simulated clock cycles. One time unit after **every** rising edge, both sides fold
`{state, latch, veto, led}` into a per-segment 32-bit checksum (`acc = acc * 31 + sample`). At
each segment boundary the testbench compares the final four signals *and* the checksum.

So the claim is: **the RTL and the twin produced the same four output signals on every one of
those 13,239,637 cycles, up to a 32-bit checksum collision, for these stimuli.** It is not a
proof of equivalence for all inputs, and it compares only those four signals. Internal registers
other than `current_state` are not compared directly; they matter only through the outputs.

**Correction (after PR #101 merged).** The first version compared values only at the 1,526
segment boundaries. About 98% of the cycles (12,944,644) lie inside 68 long segments, the
8.4M-cycle idle run and the 68,000-cycle evaluations, and only their last cycle was checked. An
external review pointed out that "13.2M cycles" overstated that. Testing it showed the gap was
real: an RTL that pulses `veto_signal` for one cycle, 100 cycles into EVALUATING, passed both the
boundary-only comparison (0 mismatches) and the Cathedral testbench (8/8). The per-cycle checksum
was added to close that gap.

### Negative controls (`tools/hw_negative_controls.py`)

| Broken copy | Mismatching segments |

| One expected final value flipped | 1 |

| RTL threshold 191 → 192 | 3 (mainly the directed `threat=191` segment; random segments rarely hit 191 exactly) |
| RTL timing floor 68000 → 67999 | 27 (4 with boundary-only comparison) |
| RTL one-cycle veto glitch 100 cycles into EVALUATING | 45 (**0** with boundary-only comparison) |

The script also runs the real RTL and vectors first, and requires them to pass.

## Behaviour worth knowing (from the RTL, reproduced by the twin)

- Any `trigger_in`, or `threat_level >= 191`, on a clock edge starts EVALUATING. **It cannot be
  cancelled.** Dropping the trigger does not stop it, and only reset leaves the state.
- `latch_state` and `veto_signal` rise on the **68,001st** edge after the triggering edge
  (about 680 µs at 100 MHz). **The veto is not asserted during those 68,001 cycles.** The Cathedral
  testbench accepts any value from 68,000 to 68,010; the twin test pins it to exactly 68,001.
- Once TRIGGERED, no input except reset changes anything. Unknown state encodings fail safe to
  TRIGGERED.
- During EVALUATING, `status_led` shows bit 23 of a free-running counter. The vectors include one
  segment where that bit is 1.

## Shared vectors

`vectors/lucifer_latch_vectors.txt` is generated by `tools/gen_latch_vectors.py`, which is
deterministic with a fixed seed. Each line holds
`cycles rst_n trigger_in threat_level exp_state exp_latch exp_veto exp_led exp_checksum`. The
expected values come from the twin, and the RTL testbench checks them. The test
`test_vector_file_matches_generator` fails if the file is stale.

## Cosmetic issue in the Cathedral testbench

`check()` takes `input [255:0] name`, which holds 32 characters, so longer check names are
printed with their start cut off (for example `ng floor ~= 68000 cycles`). The checks themselves
are unaffected. It is left as is so the file stays byte-identical to its source.

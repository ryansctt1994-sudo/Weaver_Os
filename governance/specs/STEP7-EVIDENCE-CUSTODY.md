## Goal

An operator who holds the ledger must be unable to rewrite history **and** the trusted
reference together without an independently controlled witness detecting the substitution.

This is measurable. The acceptance tests in section 6 define it.

## The problem, stated concretely

Step 6 control C8 shows the gap. A party that holds the ledger can rewrite every entry, recompute
every digest, and publish a matching anchor and state digest. `state_report` returns
`ANCHOR_MATCHED`, and that status is correct about the arithmetic. It says nothing about who
wrote the history. Any design in this document must address that directly.

## Design

### 1. Witness keys the operator does not hold

A witness is a party that signs **checkpoints**. Checkpoints are signed with Ed25519, and the
keys are held by someone other than the ledger operator. The verifier accepts only signatures
from a pinned set of witness public keys, supplied out of band. A key taken from the snapshot
under test is never trusted.

This follows the pinned-root pattern already used by `triadic_controls`.

### 2. Checkpoint content

A checkpoint signs a canonical (WX-CJSON-1) statement with these fields:

- `schema`: `wx-checkpoint-1`
- `ledger_id`
- `checkpoint_seq`: the witness's own counter, strictly increasing
- `chronicle_root`, which already binds both roots' lengths and heads
- `roots`: `{AUTHORITY, REJECTION}` → `{length, head}`
- `witness_id`

### 3. Witness behaviour: append-only and fork-refusing

A witness signs a new checkpoint only if the new state **extends** its last signed state. To
check that, it requires the entries from its last checkpoint onward. For each root, the entry at
the old length must have the old head as its `receipt_digest`. Since receipts already link through
`predecessor_digest`, that check is a prefix check.

If the new state does not extend the last signed one, the witness refuses to sign. Refusal is
a logged event, not an error to be hidden.

### 4. Verifier behaviour

`verify_snapshot` gains an optional witness requirement. A snapshot is accepted as witnessed only
if:

- a checkpoint carries a valid signature from a pinned witness key;
- the snapshot extends that checkpoint (the same prefix check as the witness);
- the checkpoint's Chronicle Root matches the snapshot.

As implemented, a consistent result is `CHECKPOINT_CONSISTENT`, never `WITNESSED`, and every
report carries `independence: NOT_ESTABLISHED` (GD-0005 D14). Whether the witnesses are
independent of the operator is for whoever pinned the keys to state, with where the keys came
from.

### 5. Publication cadence

A rewrite is detectable only against a checkpoint that already exists. So the detection window is
the time between checkpoints. Publication must be frequent and must happen automatically.

Silence is not proof. A witness that stops receiving checkpoints can only report absence. The
verifier must report "no checkpoint since N" and never report the history as current.

## What this detects

These are design claims. None has been tested.

- Truncation or rewriting **after** a signed checkpoint, provided the witness saw the honest
  history before the rewrite.
- A complete recomputation that disagrees with any signed head at or before the checkpoint.
- A witness that is shown two different histories at the same checkpoint (a fork), if the
  witnesses compare notes or the pinned set has more than one member.

## What this does not detect (stated limitations)

These limitations are also design statements, not measurements.

- **A rewrite before the first checkpoint.** If no witness ever saw the honest history, a
  self-consistent alternative is indistinguishable from it. That case must be reported as
  UNWITNESSED, not authentic.
- **A rewrite after the last checkpoint.** It is undetectable until the next checkpoint is
  published. Detection latency equals the checkpoint interval.
- **Witness key compromise or collusion.** One compromised witness is caught only if another
  witness saw the honest history. With a single witness, nothing is caught.
- **Withheld publication.** Detected only as absence (section 5).
- **The operator's own clock, and what the witness was told.** Checkpoints bind content, not
  wall-clock truth.

## The blocker that code cannot remove

An "independently controlled" witness is a second party: another person or organization that
holds a key and runs a witness. The repository cannot supply one. This is the same organizational
blocker as C-DUAL-001.

Until a second party exists, the implementation can still be built and tested. In that case
every report must say the witness is **simulated by a key holder inside the test harness**, and the
status must remain W0.

## Custody rules (proposed)

These rules answer four questions raised in review. They are proposals. None is implemented, and
none is witnessed.

### Who controls the anchors

- The ledger operator controls its own copy of the ledger. It may **submit** anchors to witnesses,
  but it cannot sign a checkpoint.
- A checkpoint has authority only if a pinned witness key signed it (design section 1). The
  operator's copy of a checkpoint carries no weight in verification.

### Who can replace them

- No party can replace a checkpoint a witness has signed. A witness refuses any state that does not
  extend its last signed checkpoint (design section 3). A replacement would be a fork, and forks are
  refused.
- Witness keys change only by rotation. Rotation must be signed by the existing witness set, be
  published, and be recorded in the ledger's governance log. **The rotation procedure is not defined
  yet; this is an open requirement.**
- The operator cannot rotate witness keys. With more than one pinned witness, no single witness can
  either.

### How independently held evidence is compared

- The verifier fetches checkpoints from witness-controlled channels, never from the snapshot under
  test. It needs at least two channels the operator does not control. With one channel, the result
  is UNCORROBORATED.
- Comparison is by prefix consistency: the snapshot must extend each fetched checkpoint's Chronicle
  Root. Fetched checkpoints are also compared with each other.
- **Independence is a property of people and organisations, not of code.** A second person with
  access is not automatically independent custody. Independence requires that the witness takes no
  instructions from the operator, that the witness's key material is not on the operator's systems,
  that the operator cannot write the witness's storage, and that these facts are attested by the
  witness operator. Code can verify signatures and consistency. It cannot prove independence.

### What happens when the evidence disagrees

Every row is reported. No row is repaired automatically.

| Observation | Report | Required action |
|---|---|---|
| Snapshot extends the latest checkpoint, corroborated by at least two independent channels | CHECKPOINT_CONSISTENT, CORROBORATED (the code counts distinct pinned witnesses; that the channels are independent is not checked) | none |
| Snapshot is shorter than, or forks from, a signed checkpoint | FORKED or REGRESSED, REFUSED | freeze ledger extension; escalate to witnesses and steward |
| Two witnesses sign conflicting checkpoints at the same length | SPLIT_VIEW, REFUSED | freeze; investigate fork or key compromise |
| A witness refuses a checkpoint the operator submitted | refusal logged and reported | the operator must explain; a refusal is evidence, not noise |
| No checkpoint newer than N intervals | ABSENT_SINCE(N); never CURRENT | escalate |
| Only one channel corroborates | UNCORROBORATED | not witnessed |

- Resolution is a governance decision, recorded in the governance log with the disagreement
  evidence attached. The code can detect and report disagreement. It cannot decide which party is
  honest.

## 6. Acceptance tests (required before any closure claim)

| # | Test | Required result | Implemented as (`tests/custody/test_acceptance.py`) |
|---|---|---|---|
| A1 | Honest checkpoint signed, snapshot extends it | accepted as CHECKPOINT_CONSISTENT (was "WITNESSED"; see GD-0005 D14), independence NOT_ESTABLISHED | `test_a1_honest_checkpoint_and_extending_snapshot_are_consistent` |
| A2 | Operator recomputes the whole chain and re-issues the anchor after a signed checkpoint | refused: fork against the signed head | `test_a2_full_recompute_after_a_signed_checkpoint_is_refused_as_a_fork` |
| A3 | Operator rewrites before the first checkpoint | accepted, reported UNWITNESSED, never authentic | `test_a3_rewrite_before_any_checkpoint_is_unwitnessed_never_authentic`, and `test_known_limit_a_rewrite_no_witness_ever_saw_is_indistinguishable` |
| A4 | Witness is asked to sign a regressing or forked state | refuses, and logs the refusal | `test_a4_witness_refuses_a_forked_state_and_logs_the_refusal`, `test_a4_witness_refuses_a_regressed_state` |
| A5 | Checkpoint signed by a key not in the pinned set | rejected | `test_a5_checkpoint_from_an_unpinned_key_is_rejected` |
| A6 | Pinned keys supplied by the snapshot under test | rejected: keys are never taken from the input | `test_a6_a_checkpoint_cannot_carry_its_own_key`, `test_a6_attacker_signing_as_a_pinned_witness_fails_the_signature`, `test_a6_pinned_keys_must_be_supplied_by_the_caller` |
| A7 | Truncation after a signed checkpoint | refused: shorter than the checkpoint | `test_a7_truncation_after_a_signed_checkpoint_is_refused` |
| A8 | Absence: no checkpoint for the newest N entries (was "N intervals"; see GD-0005 D14) | reported as `NO_CHECKPOINT_FOR_LAST_N_ENTRIES`, never as `COVERED_TO_HEAD` | `test_a8_absence_is_reported_in_entries_never_as_covered` |

The mutation checker removes the truncation check, the fork check, the pinned-key check, the
signature check, the split-view check and the witness's refusal path; each is detected by the
named test. The pinned-key mutation is detected by a crash, not by a wrong verdict.

## Interaction with the existing digest

`wx-state-digest-1` is unchanged. Checkpoints bind the same `chronicle_root`. If the digest
preimage ever changes, that is a new schema version (`wx-state-digest-2`), and the old version is
refused rather than reinterpreted.

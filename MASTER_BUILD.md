# Weaver Nexus Master Build v1

**Decision date:** 2026-07-14  
**Inventory:** 61 current repositories  
**Maximum active canonical repositories:** 3  
**Authority:** NONE

> No mechanism may silently convert uncertainty into authority.

## Executive decision

The portfolio will converge on three active repositories. This is the minimum defensible split because the portfolio contains three materially different trust domains and multiple software licenses.

1. `Weaver_Os` — constitutional control plane and verification spine.
2. `Lumen` — executable evidence, Chronicle, receipt, replay, and bounded agent-runtime integration.
3. `Math_Build1994` — formal methods, Auto Scientist, proof receipts, benchmarks, RTL, and mathematical research.

Everything else is assigned one of four dispositions: selected integration, pinned donor/reference, research archive, or quarantine. Existing repositories are not deleted by this baseline.

## Migration law

No source is moved merely because its repository name appears in an intake list. Every imported component requires:

1. immutable source pin;
2. upstream and author identity;
3. license compatibility review;
4. file-level provenance record;
5. exact build or test command;
6. clean-environment transcript;
7. positive and negative-path fixtures;
8. artifact hashes;
9. explicit non-claims;
10. a supersession pointer from the old repository.

## Migration sequence

### Phase 0 — baseline

- Freeze this three-repository architecture.
- Record all 61 repositories in `portfolio/master-build.v1.json`.
- Preserve current repositories and open pull requests.
- Capture current default-branch pins before any code transplant.

### Phase 1 — control-plane consolidation

- Reconcile selected Weaver OS PR material rather than merging overlapping branches wholesale.
- Promote persistent replay, failure-atomic emission, receipt verification, and Chronicle contracts.
- Keep authority `NONE` until independent reproduction.

### Phase 2 — executable evidence runtime

- Consolidate Lumen Chronicle, receipt, replay, replay cache, authority-verifier interface, and witness package.
- Add donor adapters one at a time behind disabled-by-default manifests.
- Reject runtime invocation when a pin, license, receipt, or authority lease is missing.

### Phase 3 — formal and Auto Scientist lab

- Consolidate Math Build and AutoProof.
- Repair toolchains and remove proof placeholders.
- Add formal/empirical claim separation and machine-readable receipts.
- Integrate T81/ternary assets only after exact source and test evidence are captured.

### Phase 4 — supersession

- Add redirect READMEs to repositories whose unique material has been integrated.
- Archive only after file hashes, provenance, and supersession pointers are complete.
- Quarantine unresolved or unsupported claims; do not erase their history.

## Current evidence boundary

This baseline is a repository architecture and migration contract. It does not prove that all selected code has been merged, built, tested, independently reproduced, formally verified, hardware validated, or production authorized.

The next promotion target is a clean three-repository execution corridor with source-bound receipts and an independent witness package.
